# Inventário de código `unsafe`

O compilador recusa `unsafe` fora de `arch/`, `mm/` e `sync/`
(`#![deny(unsafe_code)]`, D-008). Esta lista tem de estar sempre igual ao
código: quem acrescenta ou remove `unsafe` atualiza-a no mesmo PR.

Verificação rápida: `git grep -n "unsafe" -- kernel/src`.

| Ficheiro | O que é unsafe | Porquê é necessário | Porquê é seguro | Dono |
|---|---|---|---|---|
| `kernel/src/arch/x86_64/port.rs` | 6 blocos `asm!` (`in`/`out` de 8/16/32 bits); `unsafe fn port_in/port_out`; `unsafe fn Port::new`; 2 blocos em `read`/`write` | o Rust não tem instruções de I/O de portas | o contrato de `Port::new` garante que a porta não pode violar a segurança de memória; os blocos só reencaminham esse contrato | CLAUDE |
| `kernel/src/arch/x86_64/cpu.rs` | (Fase 4) `sti`, `pushfq; pop`, `sti; hlt`; `cli`/`sti`/`hlt` sem `nomem` (D-037). Também: blocos `asm!` para `cli`, `hlt`, CR0/CR2/CR3/CR4, `rdmsr`/`wrmsr`, `wbinvd`, `invlpg`, `int3`; `unsafe fn wrmsr`, `program_pat`, `write_cr3`. Os restantes blocos `asm!` (`cli`, `hlt`, `mov cr2`, `int3`) são da Fase 2 | instruções privilegiadas | `cli`/`hlt`/ler CR2 não tocam em memória; `int3` só depois de a IDT estar carregada, e o handler devolve todos os registos intactos; o `asm!` do `int3` **não** usa `nomem`/`nostack`, porque o CPU empilha o frame e o handler escreve na memória da consola (issue #7) | CLAUDE |
| `kernel/src/arch/x86_64/gdt.rs` | `unsafe impl Sync for CpuTables`; 2 escritas (TSS, GDT); 1 bloco `asm!` (`lgdt`, far return para recarregar CS, `mov` de segmentos, `ltr`) | o CPU lê (e escreve o bit busy da TSS) por trás do compilador; recarregar CS só é possível em assembly | escrito uma vez por quem ganha o `AtomicBool`, antes de o CPU o conhecer; os descritores novos têm o mesmo privilégio e modo que os do Limine | CLAUDE |
| `kernel/src/arch/x86_64/idt.rs` | `unsafe impl Sync for Idt`; 1 escrita; 1 bloco `asm!` (`lidt`) | carregar a IDT | escrita única antes do `lidt`; todas as entradas presentes apontam para stubs válidos com o seletor de código do kernel | CLAUDE |
| `kernel/src/arch/x86_64/trap.rs` | `global_asm!` (stubs e rotina comum); leitura do `extern static` `kitty_trap_stubs` | a entrada de uma interrupção não pode ser escrita em Rust | os stubs guardam e repõem todos os registos e mantêm a pilha alinhada a 16 (ver comentário no ficheiro); a tabela está em `.rodata` e nunca é escrita | CLAUDE |
| `kernel/src/arch/x86_64/irq.rs` | 1 bloco `asm!` (`int 0xF0`) no autoteste | disparar o vetor de teste por software | a gate está presente e o handler só incrementa um atómico; sem `nomem`/`nostack` | CLAUDE |
| `kernel/src/arch/x86_64/pic.rs` | `Port::new` para 0x20/0x21/0xA0/0xA1/0x80 | programar o 8259 | o PIC não faz DMA nem muda o mapa de memória; o pior caso é mascarar ou desviar IRQs | CLAUDE |
| `kernel/src/arch/x86_64/legacy.rs` | `Port::new` só para portas da allow-list (i8042 0x60/0x64, PIT 0x40–0x43, CMOS 0x70/0x71) | dar a drivers sem `unsafe` acesso aos seus dispositivos | nenhum destes dispositivos faz DMA; offsets fora da lista devolvem `None`; as escritas com efeito no sistema inteiro (comandos do i8042 fora de `I8042_ALLOWED_COMMANDS`, bit NMI do CMOS) são filtradas antes de chegar à porta | CLAUDE |
| `kernel/src/sync/irq_spinlock.rs` | `ManuallyDrop::drop` do guard interno | libertar o lock antes de repor as interrupções | é chamado uma só vez, no `Drop` do próprio guard | CLAUDE |
| `kernel/src/arch/x86_64/stacks.rs` | `unsafe impl Sync for StacksCell`; 1 bloco `asm!` (mudar RSP e chamar) | a troca de pilha só se faz em assembly | o Rust nunca lê/escreve a memória das pilhas pelo static; a pilha nova está mapeada RW e a função nunca volta | CLAUDE |
| `kernel/src/mm/paging.rs` | leitura/escrita voláteis de entradas de tabelas de páginas pelo HHDM | as tabelas são memória física lida pelo CPU | só se acede a frames que são tabelas do `AddressSpace` (emprestado `&mut` para escrever) ou do Limine (só leitura); índice sempre `% 512` | CLAUDE |
| `kernel/src/mm/vmm.rs` | `extern static`s dos símbolos do linker; `program_pat` e `write_cr3`; `unsafe fn map_mmio`; leituras/escritas voláteis de MMIO; autoteste MMIO | mudar de espaço de endereçamento e aceder a registos de dispositivos | antes do CR3 verificamos que o código e a pilha estão mapeados e que a auditoria W^X passou; MMIO recusa RAM e verifica limites/alinhamento | CLAUDE |
| `kernel/src/arch/x86_64/selftest.rs` | blocos de falha propositada: ler endereço não mapeado; `mov rsp` inválido + `int3`; escrever em `.text`; executar `.data`; escrever na IDT; escrever depois do fim de uma alocação grande | provocar falhas de propósito | só existe com as features `selftest-*`; o handler nunca volta. Cada acesso que falha é **uma instrução em `asm!`** sem `nomem`/`nostack` (e não `read_volatile`/`write_volatile` ou chamar um ponteiro de dados), porque o handler escreve memória Rust e usa a pilha antes do panic (issue #7) | CLAUDE |
| `kernel/src/arch/x86_64/serial.rs` | 1 bloco: `Port::new` para 0x3F8..0x3FD | aceder à UART COM1 | a 16550 não faz DMA; o pior caso é output corrompido | CLAUDE |
| `kernel/src/arch/x86_64/qemu.rs` | 1 bloco: `Port::new(0xF4)` | sair do QEMU nos testes | só existe com a feature `qemu-exit`; a escrita termina a VM | CLAUDE |
| `kernel/src/arch/x86_64/boot.rs` | atributos `#[unsafe(link_section)]` (5) e `#[unsafe(no_mangle)]` (1); 1 bloco `slice::from_raw_parts_mut` do framebuffer | o Limine encontra os requests pela secção; o linker encontra `kernel_entry` pelo nome; o framebuffer só nos chega como ponteiro | secções dedicadas só com estes statics; nome único; o Limine garante o mapeamento de `pitch*height` bytes, validamos ponteiro/tamanho e um `AtomicBool` garante que o `&'static mut` só é criado uma vez | CLAUDE |
| `kernel/src/sync/spinlock.rs` (Fase 4) | `unsafe impl<T: Sync> Sync for SpinLockGuard` | o guard tem um ponteiro bruto `PhantomData<*mut ()>` para ser `!Send`, o que também lhe tira o `Sync` automático | `&guard` só dá `&T`, por isso pode ser partilhado exatamente quando `T: Sync` (mesma regra que a `MutexGuard`) | CLAUDE |
| `kernel/src/sync/spinlock.rs` | `unsafe impl Sync for SpinLock<T>`; 2 blocos (`Deref`/`DerefMut` do guard) | um lock transforma acesso partilhado a `UnsafeCell` em `&mut T` | só existe um guard de cada vez (garantido pelo `AtomicBool` com Acquire/Release); `T: Send` exigido | CLAUDE |
| `kernel/src/mm/pmm.rs` | `unsafe impl Send for Pmm`; inicializar e criar o slice da base de dados de frames; `write_bytes` para limpar frames; `unsafe fn PhysFrame::from_raw`; 2 acessos voláteis no autoteste | a memória física só é acessível por ponteiros (via HHDM) | a base de dados fica numa região usable reservada só para ela e inicializada antes de criar o slice; só se limpa um frame sem dono (refcount 0) ou acabado de tirar da lista, com o lock do PMM; `from_raw` documenta que cada referência só pode ser recriada uma vez | CLAUDE |
| `kernel/src/mm/heap.rs` | `unsafe impl GlobalAlloc`; leitura/escrita do link nos pedaços livres; `write_bytes` ao libertar; `PhysFrame::from_raw` ao desmapear; `_rdtsc`; autoteste com alloc/dealloc diretos | um alocador global trabalha com memória não tipada | contrato do `GlobalAlloc` explicado no `unsafe impl`; só se toca em pedaços livres de páginas do heap mapeadas; os links são validados (intervalo + alinhamento) antes de serem usados | CLAUDE |
| `kernel/src/mm/hhdm.rs` | nenhum (só aritmética de endereços) | — | — | CLAUDE |

Dependências externas com `unsafe`: crate `limine` (leitura volátil das
respostas do bootloader). Usado só em `arch/x86_64/boot.rs`.
